# 0.1.0-experiment 跨设备测试

此页为旧版本记录。当前0.1.1-experiment以Windows/macOS为目标，请使用docs/desktop-testing.md及start-windows.bat / start-macos.command；手机测试不在当前发布范围。

这是可运行的合成数据交互测试，不是完整求职MVP。支持条件分组、偏好排序、组内置顶、选择/隐藏及日志导出。不支持真实简历导入、BOSS采集、AI判断、财报采集或外部操作。无需模型Key、账号、依赖安装或构建。专业匹配为预设样例。

## Windows

从仓库下载ZIP并解压，浏览器打开web/index.html。推荐Chrome或Edge。网页无第三方资源、无联网请求，不上传数据。

可选：安装Python 3.10+后，在解压目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory web
```

访问 http://127.0.0.1:8765 。服务结束按Ctrl+C。已有Python工具测试按README执行。

## iOS（Safari）

iOS只测试浏览器页面，不运行Python/桌面Chrome采集。系统文件预览可能不执行HTML脚本，因此不能以“文件App预览正常”代替浏览器运行测试。

推荐在Windows与iPhone连接同一可信Wi-Fi后，由Windows仅托管web目录：

```powershell
python -m http.server 8765 --bind 0.0.0.0 --directory web
```

在Windows用ipconfig查看局域网IPv4，iPhone Safari打开 http://该IPv4地址:8765 。必要时允许Python通过Windows专用网络防火墙；不要开放公网端口，不把整个项目目录作为服务根目录。服务只用于无个人数据的静态样例，测试后Ctrl+C停止。无法连接先核实同网段、访客Wi-Fi隔离及防火墙，不视为匹配逻辑故障。

也可由测试者将web/index.html部署到自有静态站点。仓库公开不代表GitHub Pages已启用；本包不承诺iOS独立采集。没有另一台托管设备时，需要先提供静态托管地址才能进行可靠的iOS浏览器测试。

## 测试步骤及预期

1. 初始18K、必须双休：S01/S06进入披露条件满足；S02值得核实；S03/S04/S05存在取舍。S06重大风险仍突出，不因条件满足变成已获认可公司。
2. 改为双休不在意：S04可进入披露条件满足，但经验差距仍保留；S02固定薪资仍未知。
3. 改为固定薪资底线20K：S06转为存在取舍，不能用公司前景抵消薪资。
4. 切换待遇/职责/前景顺序；组内置顶一个岗位，确认不跨越条件分组。点击应用条件会清除本轮置顶，恢复系统顺序。
5. 选择/取消、隐藏岗位；重置后选择与隐藏清空。刷新页面会清空内存，不代表持久化功能已实现。
6. 导出测试日志，确认JSON文件真实保存。iOS如打开预览，用分享菜单存储到文件。没有下载成功也请反馈该失败。

## 日志回传

导出dagongren-test-log.json后人工发送给项目维护者或当前开发对话；没有后台自动回传。另附系统版本、浏览器版本、成功/失败步骤、预期与实际表现，可附不含个人信息的截图。不要上传真实简历、Cookie、令牌、账号、局域网地址或个人报告到公开Issue。

日志只记录版本、事件名、相对运行时间、合成岗位ID与选择计数，不保存输入值、自由文本、完整错误栈或设备标识。它用于排查交互步骤与运行时异常，不足以单独衡量推荐准确率或决策时间改善。关闭页面前请导出。
