# 开源边界与事实证据

## 发布边界

公开：审核过的通用逻辑、结构契约、测试与合成样例。本地保留：简历及履历、联系方式、具体业绩、判断报告、来源快照、数据库、浏览器profile、Cookie、令牌、配置和事实ID盐。旧文档可能包含个人职业轨迹，不能只替换姓名后公开。

本仓库采用根目录默认排除、代码文件逐项允许的策略；不上传data或references。参考项目复用时仍须单独保留对应许可。旧脚本中存在个人化选择和本机参数，尚未全部改造，暂不进入发布范围。发布扫描只读允许清单，不输出匹配到的敏感内容；通过扫描不等于绝对匿名，仍需人工检查。

## 事实ID与证据链

从简历工作内容和业绩原文逐行提取，状态为candidate-unconfirmed。ID由本地随机盐进行HMAC生成，不把姓名、公司名或原始履历直接写进ID。相同盐、经历序号、字段和原文生成相同ID；修改原文或移动经历可能产生新ID，不承诺跨设备自动一致。ID并不是脱敏后的公开数据，不发布事实库和盐。

每条事实保留sourceHash、原文路径及精确引文。评审引用candidateFactIds必须解析到同轮candidate来源，且存在完全相同的已校验引用。支持数组路径，例如experiences.0.responsibilitiesRaw。

## 本机试跑记录

真实数据仅在data/private及本地数据库中处理。历史20家草稿迁移增加候选人引用；主题检索仅提出关联，不验证充分性、因果或岗位胜任力。未知保持未知，不提升评审状态。后续逐条人工或模型语义复核后再建立确认机制。

## 可复跑顺序

原文导入 → 评审草稿迁移 → 本地事实提取与关联 → 引用验证 → 语义复核 → 用户确认。candidate_facts.py目前迁移入口仍读取本地固定试跑文件，通用函数extract_facts不依赖真实用户样例。公开测试仅使用合成片段。
