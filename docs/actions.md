# 历史动作阶段：限定授权、只读刷新与人工接管台账

本页保留早期人工接管设计。当前MVP按用户要求只启用收藏执行，沟通投递由本人完成；最新使用及验收以[收藏MVP](favorite-mvp.md)为准。历史沟通记录可回看，但不再授权新沟通任务。

当前为阶段9的**部分交付**：授权、刷新、人工接管和平台状态观察已接入，自动收藏／自动沟通适配器尚未上线。没有真实发送、附件上传、自动回复或自动投递能力。本文件不将人工接管冒称系统执行成功。

## 为何区分两种状态

“平台已显示收藏”与“本系统完成收藏”是两件事。进入聊天、看到“继续沟通”或点击过按钮，均不能证明具体消息已经发送。当前台账的`systemExecuted`始终为false，`messageSent`始终未核实，附件始终未授权。会显示最后观察的时间与证据，不承诺此刻仍保持同一状态。

对收藏，只有刷新文件中唯一、明确的头部“已收藏”按钮证据才可记录“观察到收藏”。“感兴趣”尚未经过行为映射验收，不能猜测等同收藏。没有识别到支持的控件时显示未知，不能标成“未收藏”。沟通接管目前只能保留结果未知，不升级成“已发送”。

## 顺序与脚本

1. 在第9节完成有效报告和本人选定的优选／候选岗位。第10节列出具体岗位和两个独立人工接管范围：收藏、沟通。逐项勾选，阅读范围后确认；每批1—20项，授权30分钟有效。发消息内容、附件及回复不在范围内。保存授权不会操作平台。
2. 使用已经登录的独立Chrome测试窗口；不操作日常浏览器。必要时本人完成登录。先确认调试端口，再执行：

```text
node scripts/observe_job.mjs --job https://www.zhipin.com/job_detail/替换为实际岗位.html --output data/private-actions/新的观察目录 --endpoint http://127.0.0.1:9333
```

输出目录必须全新，父目录先建好；不重复覆盖。多个平台页时追加`--tab-id 实际标签ID`，不自动选一个。脚本先检查当前页登录／安全状态，再导航指定岗位、同主体公司页及返回岗位。只读DOM，不点击收藏或沟通，不请求隐藏接口、不发送文本或附件。登录、安全验证、断连、主体不明时停止并保存失败状态。

3. 把生成的`observation.json`导入第10节，核对证据并点击对应任务的“导入刷新并开始人工接管”。要求岗位和公司观察均在5分钟内，容许30秒时钟偏差；主体一致，报告仍有效、授权版本未改变，职责与已配置条件证据未变化。条件不符、职责变化、授权超时或旧版本时拒绝开始，回到采集／评审／新报告。不会使用旧公司福利补足新观察。
4. 如果开始前已明确观察到收藏，就记录平台状态，不重复接管。否则由**本人在平台完成操作**。沟通按钮可能触发平台自带行为，需本人核对页面，不由项目自动点击。系统台账先写入“待本人操作／待证据”，不会因崩溃或刷新而丢失未决任务。
5. 操作后再次运行只读刷新脚本，使用新的输出目录。导入操作后的新观察并明确核对，不能重复使用开始前文件。只对符合要求的收藏控件记录平台收藏观察；其他结果维持未知。观察失败或结果未知不自动重试，不标成功。
6. 已开始的未知结果须补证核对；不能通过“撤销”抹掉不确定记录。尚未开始的授权可明确撤销。整个工作区数据目录内跨记录防重复，但不同设备／不同数据目录尚无共享账本，不能保证跨设备全局去重。

## 证据、存储与报告

SQLite台账位于所选私有工作区目录，事务内保存授权和事件；具体任务绑定报告版本、证据指纹、岗位及公司。授权期过后只能做结果核对，不能继续开始新接管。新报告或重排会改变版本，需撤销旧的未开始授权再重新明确授权；不自动扩大范围。

台账保存原始前后观察、hash和时间；不打印个人资料。导入观察由本人复核，来源没有数字签名或远程认证，不能声称独立核验。更改本地JSON／数据库的恶意行为不在完整性保证范围。操作范围确认与实测结果分别留存，不把人工证词当系统自动执行。

最新台账标记会在工作区岗位卡及新导出的私人HTML／JSON显示；以前导出的文件不自动更新。报告仍包含私人资料，不能上传开源仓库。当前导出没有平台账号标识，切换BOSS账号时应使用不同私有数据目录；尚未实现账号绑定及跨账号授权隔离，不能用于自动执行。
