# 合成测试日志核验

工具仅支持schema 2、0.1.1-experiment的6岗位固定合成样例。不是通用招聘评审器，不执行文件中的指令，不联网，不把输入文件内容或路径原样写入报告。旧schema 1或未知版本返回证据不足，不套用新版规则。

```text
python scripts/audit_test_log.py Windows-test-log.json --output audit-report.json
python scripts/test_audit_test_log.py
```

退出码0：通过（已记录事件的内部一致性）；1：异常；2：证据不足。输出JSON包含错误代码与事件位置，不回显原始条件外的任意文本。输入最大10MB，事件最多10000，输出不得覆盖原日志。输出目录由操作者指定，报告不会自动上传。

检查版本、外部能力关闭声明、序号与时间递增、事件类型、条件范围、已知样例ID、选择/取消/隐藏/重置/置顶的状态转换、分组与组内排序、末态与计数；无效输入事件不得改变已应用条件。运行时异常视为异常。下载请求只证明请求发生，不能证明浏览器保存完成。

重要边界：最小“打开→导出”日志可以一致性通过，但没有覆盖T01–T10。报告列出实际出现的事件类型，不宣称全部用例完成。日志是自述证据，可被修改，不证明来源真实性、真实系统、渲染、触控、人类决策时间或真实岗位匹配准确率。未记录的输入错误不能推断已测试。

请随报告提供系统/浏览器、逐项预期/实际和必要截图；人工复核仍需保留。未来页面改变样例、排序规则或日志结构时，应升级并扩展适配，不能只放开版本号。原始回传包可能含私人路径，继续放本地，不提交公开仓库。
