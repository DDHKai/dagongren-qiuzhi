# 参考项目README结构拆解

核对日期2026-11-11，来源为下列仓库当前公开README；这是文档结构观察，不是对全部功能的实测认证。上游会变化，文中的许可状态不代替未来复用时的具体版本审查。

## 1. 求职舱：桌面产品型

[来源](https://github.com/kyle-kw/ai-job-app/blob/main/README.md)

结构：名称与用途 → 数据位置 → 能力 → 首次使用 → 系统支持 → 隐私 → 开发/运行 → 检查 → 构建与发布 → 致谢和许可。

作用：让普通用户找到使用路径，让开发者找到构建路径；隐私和平台边界独立成节。我们采用用户/开发者分层、数据边界和能力状态表，不能借用其安装包、模型调用或系统兼容承诺。当前README声明MIT。

## 2. 自动投递项目：任务执行型

[来源](https://github.com/bazxhy/Automated-Resume-Submission/blob/main/README.md)

结构：任务价值 → 功能表 → 安装/配置 → 命令与交互 → 工作流 → 搜索、风险与匹配模块解释 → 计数 → 目录与技术栈 → 许可。

作用：用户能理解从输入到动作的链条，运行参数和结果记录有对应关系。我们采用流程与日志说明，但不把点击沟通等同附件送达，不声称已有自动投递，也不照搬其个人化阈值。当前README声明MIT。

## 3. 岗位采集工具：CLI/技能型

[来源](https://github.com/eatmoreduck/boss-zhipin-scraper/blob/master/README.md)

结构：定位/版本/环境 → 使用边界 → 快速上手 → 特性 → 多种安装入口 → CLI参数与示例 → 聚合输出及目录 → 故障与维护说明。

作用：明确输入、命令和JSON/CSV结果，便于排查采集环境。我们采用可复制步骤、输出定义及限制披露，不复制其接入方案或访问稳定性承诺。README显示MIT标识，具体代码仍须核对LICENSE及文件头。

## 我们的文本结构与引用边界

独立组织为定位/真实能力 → 体验 → 规划 → 测试与日志 → 隐私 → 参考与许可 → 免责声明 → 贡献。不将上游功能包装成我们已实现；不转载README长段落、截图、Logo或代码。当前公开实现没有引入上述三库代码，参考关系是设计研究，不是依赖、派生或作者背书。未来复用须记录源仓库、精确提交、文件、许可、版权声明及修改点，不能只写一句“感谢”。
