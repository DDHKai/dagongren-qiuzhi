# MVP范围：筛选决策与授权收藏

当前范围按用户确认收敛：帮助经历梳理、岗位与公司筛选、证据说明、个性化选择，并在**具体岗位明确授权后帮忙收藏**。简历发送、自动沟通、自动回复及附件上传仅保留升级口，当前不执行，也不作为MVP完成条件。用户自行在BOSS沟通和投递。

## 使用顺序

1. 启动本地工作区及项目的独立Chrome，用户本人登录。需要Python 3.10+、Node 22+和已安装的Chrome。先完成候选事实、岗位预筛、重点岗位人工复核及本轮选择。
2. 第10节点击“只读核对当前BOSS账号”。程序在独立Chrome中查看账号安全中心的可见账号管理栏目，不修改设置、不读取Cookie、密码或隐藏凭证。只有唯一脱敏手机号与可见昵称都可读取时才生成本地摘要；不能读取时停止，不猜测账号。
3. 核对显示的脱敏号码，填写本机备注并确认绑定。摘要采用本机私有盐计算，可见昵称不写入绑定文件；浏览器会话另作绑定。确认1小时有效，探测结果只可在5分钟内确认。重新登录、换账号或重启浏览器后重新核对绑定。
4. 勾选已选名单中的具体岗位，确认“只授权收藏”。每批1—20项，每项30分钟有效；授权与报告版本及账号绑定关联。不因为授权收藏而获得沟通、简历或回复权限。
5. 点击单项执行或本轮批量执行。系统逐项刷新账号、岗位及同主体公司，比较职责和已配置条件证据。变化、身份不明、登录墙、安全验证、过期或控件不明时停止该项，其他授权项可以继续；不会悄悄放宽条件。
6. BOSS详情页的保存入口可能为心形“感兴趣”，执行器只识别同岗位标题所在头部的唯一`.btn-interest`及精确“感兴趣／已感兴趣／取消感兴趣”，或唯一明确“收藏／已收藏”控件。“取消感兴趣”必须同时有active状态才作为已收藏证据；绝不点击该取消入口或“立即沟通”。同名、重复、禁用、不可见或标题不符时停止。
7. 已收藏的岗位不再次点击，避免反向取消。需要新收藏时，先持久记录执行尝试，再最多请求一次收藏点击。点击返回不算成功：必须重新加载并重新读取，仍为已收藏状态、岗位／公司／关键内容未变，并再次核对账号，才标记“系统收藏完成”。
8. 报告显示成功、原本已收藏、点击前停止和结果未知四种不同结果。浏览器断连或点击后无法核实，保留未知并禁止自动重试；可通过只读新观察补证，但补证只说明观察到状态，不追认由系统完成。原有人工台账仍保留，当前不再新建沟通授权。

## 账号与隐私边界

账号一致性使用可见昵称＋脱敏手机号的本机HMAC摘要，另比对Chrome调试会话摘要；不读取平台登录令牌。它用于降低误切账号风险，**不是平台实名认证或不可碰撞的账号标识**：同昵称和同脱敏号码可能碰撞。执行期间不要切换账号，也不要多人共用这一独立Chrome；暂不适合作为多租户或无人值守服务。

绑定、盐、授权、原文观察、执行记录和私有worker请求均保留在工作区数据目录，默认Git忽略。不公开整个目录，不把真实账号、简历或截图混入开源样例。不同设备／数据目录暂不共享台账；跨设备去重仍需统一账本或人工核对。系统会先看实时收藏状态，已收藏不重复点击，但不能承诺跨设备一致事务。

## 状态与恢复

- `authorized`：具体范围已确认，尚未操作。
- `ready-to-execute`：前置核对通过，尚未请求点击；崩溃后可明确撤销、重新授权，不自动续跑。
- `executing`：执行尝试已持久认领；崩溃后按未决处理，不自动重试。
- `confirmed-favorite`：匹配本次尝试的点击记录＋刷新后的收藏证据＋账号一致性核对通过。
- `observed-favorite`：只核实已存在收藏，不将观察直接等同本次系统执行完成；包括原本已收藏及未决结果经后来只读补证。
- `blocked-before-click`：明确在请求收藏点击前停止；需要重新核对后明确授权，不隐式重跑。
- `outcome-unknown`：点击可能发生但证据不足，保持未决，禁止重复。

授权期过后仍允许只读结果核对，但不能开始新点击。已经开始或结果未明的记录不能通过“撤销”抹掉。成功证据是页面披露，不是对BOSS后台数据库的独立认证；收藏也不保证岗位仍有效或会得到回复。

## 脚本、测试与升级口

工作区API负责范围和台账，`favorite_worker.mjs`为本机子进程入口，`favorite_driver.mjs`负责账号／页面／一次收藏点击，`favorite_core.mjs`包含纯策略与DOM边界。worker只支持`probe / prepare / execute / verify`四种收藏流程模式，没有发送消息或上传附件的分支。不要手工构造生产worker请求绕过工作区授权。

未来动作契约保留“岗位身份＋账号绑定＋报告证据＋具体授权＋执行尝试＋结果证据”的结构；`state.capabilities`明确把autoContact、sendResume、autoReply标为upgrade-disabled。将来增加这些功能须单独引入发送正文、附件hash、收件对象和对应成功证据，不能沿用收藏授权。当前API拒绝沟通、发送简历、自动回复和附加发送字段。

单机测试包括纯策略／DOM夹具、合成CDP子进程、真实本地Chrome界面（收藏worker使用合成替身）、Python台账／工作区测试。它们不冒称已收藏真实岗位。真实账号已完成只读探测；真实收藏已按用户指定的唯一岗位授权试跑，首次因新文案被判未决，保留首次记录并经只读重载确认已收藏；修复及回归覆盖“取消感兴趣＋active”，没有重复点击或取消。单个岗位不证明所有页面状态都已验证。新工作区仍需Windows／macOS全流程验收。

## 本轮执行与验收记录（2026-11-12）

顺序：按用户确认收敛MVP动作范围 → 只读探测账号界面及收藏控件 → 昵称/脱敏手机号本地摘要与Chrome会话绑定 → 分离prepare、一次execute及只读verify → 台账认领、授权时效、版本和防重复 → 移除新沟通授权并保留历史 → 纯策略、API、合成CDP和本地Chrome测试 → 用户指定唯一真实岗位 → 多标签时停止并按目标路径精确定位 → 用户定向收藏验收（不冒称岗位匹配推荐） → 首次保存后文案漏识别，保留outcome-unknown → 只读查明“取消感兴趣＋active” → 修复文案及关键内容指纹，加入回归 → 只读重载补证，追加observed-favorite，不重写旧尝试成零故障成功。

130项Python测试、JavaScript策略／DOM／合成子进程测试通过；真实本地Chrome界面测试使用合成收藏worker，验证账号确认、逐项授权、完成记录、重载和私人导出，未冒称该测试接触真实平台。80文件白名单无扫描发现，带空格干净目录演练通过。真实账号已只读核对，真实指定岗位仅请求一次收藏，后续均为只读验证，没有取消、再次收藏、主动沟通、发送简历或附件。

首次真实验收不是无异常完成：当前平台已收藏状态经重载确认，但台账保留首次识别失败与后续只读补证，systemExecuted不被补证追认为true。修复后的合成子进程覆盖实际取消文案、active状态、只读verify和不重复点击。所有真实请求、稳定岗位身份、过程脚本、观察、执行及补证回执保留在data私有目录，不进入公开包。没有复制真实会话临时参数到源码。

当前完成的是收藏MVP基础，不表示100家公司深评、真实筛选效果、所有BOSS页面版本或新工作区双系统部署已获验证；这些继续按阶段10验收，不以缩小动作范围替代质量验证。
